PRODUCT STORY · OCTOBER 2026

A clearer way to share agent recipes

Know what a recipe contains before you adopt it.

Skillbuffet is a reviewed marketplace for reusable AI agent recipes: inspect the files, understand the declared access, see the review status, then download an approved version for your own environment.

Product walkthroughFrom a repeatable task to a reviewed recipe

01 · The starting point

Every team has tasks it repeats.

A good recipe captures the steps, context and declared inputs a person wants an agent to follow for one job.

The opportunity is to make those instructions easier to discover and inspect before a team chooses to use them.

03 · What is inside

A recipe is a package of context and instructions.

The structured format uses a manifest to describe a capability and the files that support it.

  • ✓recipe.yaml describes identity, purpose, inputs, outputs, dependencies and adapter status.
  • ✓JSON Schemas can describe the expected shape of data.
  • ✓Instruction and adapter text explains the intended sequence and integration contract.
  • ✓One recipe per listing keeps its review and version understandable.

05 · The user experience

The marketplace helps people make an informed choice.

The product exposes useful details before download, then leaves integration and execution in the user’s environment.

Creator Submit a recipe

  1. Create an account and choose the recipe format.
  2. Upload one recipe or choose one manifest from a package.
  3. Add title, category, summary, version and declared details.
  4. Review scan findings; submit to the private admin queue.
  5. Track the decision and update if changes are requested.

Recipe user Inspect and download

  1. Browse by task, category or search.
  2. Read the saved instructions, version, review status and declared access.
  3. Sign in and download an approved recipe package.
  4. Integrate it yourself, using non-sensitive sample data first.
  5. Rate after the recorded download, if eligible.

06 · How it is built

A small product stack with clear boundaries.

The web app manages discovery, accounts, review and package delivery. It is not an agent runtime.

Trust boundary: submitted files are inspected and stored. Recipe instructions, scripts and adapters are not executed by Skillbuffet.

07 · Honest status

What the beta does today, and what it does not.

Keep the promise matched to the product. The catalogue and review workflow are the first useful slice.

Available in the product

  • Account-based sign-in and creator submissions.
  • Category discovery and approved public recipe listings.
  • Private saved versions, static inspection and admin review decisions.
  • Authenticated downloads and account-based ratings.
  • Review status and declared package details are visible to help evaluation.

Not implemented as a hosted capability

  • Automatic activation or installation on a user’s device.
  • Execution of recipe adapters, scripts or provider integrations.
  • Proof that a recipe is safe, high-quality or successful in a real workflow.
  • Runtime outcomes, time-saved, revenue or installation analytics.
  • Machine-client / MCP execution and AI-generated dynamic forms.

Static scans can flag known patterns; they are not antivirus, sandboxing or a guarantee. Download counts represent authenticated download requests, not installations or successful runs. Ratings come from account holders; identities are not independently verified.

08 · The next proof point

Start with a small set.
Prove the whole loop.

Use a focused team experiment to verify that creators can submit, admins can review, and users can inspect and download recipes.

Suggested team walkthrough

  1. Pick 10–15 test recipes with clear reuse permission.
  2. Have one creator submit a supported package.
  3. Review the scan report and admin decision together.
  4. Browse the approved listing and download it.
  5. Record format friction and runtime gaps as separate backlog items.
